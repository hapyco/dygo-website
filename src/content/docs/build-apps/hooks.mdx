---
title: Record Hooks
description: Add transactional Record lifecycle behavior with compiled Go code.
---

Record Hooks add App behavior to the Record lifecycle. Hook code compiles into the project runner. dygo does not load Go source files at runtime.

## Generate a Hook

```sh title="Terminal"
dygo generate hook crm/contact
```

The command creates `apps/crm/entities/contact/hooks.go` and updates the generated project runner. Run that runner to include the Hook:

```sh title="From the project root"
go run ./cmd/dygo db migrate
go run ./cmd/dygo dev
```

The stock `dygo` binary does not load App Hooks. See [compiled App behavior](/reference/sdk/#run-compiled-app-behavior) for production builds.

## Register behavior

```go title="apps/crm/entities/contact/hooks.go"
package hooks

import (
    "context"

    "github.com/hapyco/dygo/pkg/dygo"
)

func Register(registry dygo.RecordHookRegistry) error {
    return registry.RegisterEntity(
        "crm",
        "contact",
        dygo.RecordBeforeCreate,
        "normalize-contact",
        normalizeContact,
    )
}

func normalizeContact(ctx context.Context, hook dygo.RecordHook) error {
    return nil
}
```

Register by App and Entity identity. Do not use the route slug.

## Transaction contract

Hooks run synchronously inside the current Record transaction. If a Hook returns an error, dygo rolls back the target operation.

Use `hook.Input` in `before-validate`, `before-create`, and `before-update` when the Hook must change the current input.

Use `hook.Records` for related Record reads and writes:

```go
record, err := hook.Records.Get(ctx, "crm", "contact", 42)
created, err := hook.Records.Create(ctx, "crm", "activity", input)
```

These calls use metadata-backed Record storage and participate in the same transaction.

## External side effects

Avoid sending email or calling an external API from a transactional Hook. dygo does not have after-commit Hooks yet. A later database rollback cannot undo an external request.

Use a durable [Job](/background/jobs-and-workers/) when work can happen after the transaction.

## Validate runner wiring

```sh title="Terminal"
dygo hook validate
dygo hook list
```

If App packages changed, sync the generated runner:

```sh title="Terminal"
dygo hook sync
```

## Lifecycle events and scope

Supported events are `before-validate`, `validate`, `before-create`, `after-create`, `before-update`, `after-update`, `before-delete`, and `after-delete`. After-write events still run before commit; they are not after-commit callbacks.

The Hook also receives actor, Entity identity, numeric Record ID, old/new snapshots, and changes. Related SDK writes run framework behavior such as Activity, but do not re-enter Business App Hooks. Use explicit `AsActor` when related operations must enforce a User's access scope.

Submitted secret Field values are withheld from Hooks, including collection secrets. Hooks cannot inject secret values through `Input`. Keep collection structure and order unchanged when secret metadata is present; use explicit Record operations for structural changes.

`hook.Jobs.Enqueue` queues durable work in the same transaction. Hooks also receive Timeline and Notifications services. See [App SDK](/reference/sdk/) for the complete service inventory and explicit secret decryption rules.
