---
title: Encrypted secrets
description: Store environment secrets as encrypted project files without committing plaintext values.
---

dygo stores project secrets in age-encrypted environment files. The encrypted files can live in source control. The private master key stays outside the repository.

## Initialize secret storage

```sh title="Terminal"
dygo secret init
```

This creates the local private key and missing encrypted environment files. `dygo new` already performs initialization and seeds the development `DATABASE_URL`; do not reinitialize a generated project to fix a missing key. Restore its original key from secure backup.

## Edit secrets

```sh title="Terminal"
dygo secret edit
```

The command decrypts the development file into a temporary editor buffer, validates the result, and encrypts it again.

Select another environment explicitly:

```sh title="Terminal"
dygo secret edit --env production
```

## Read one value

```sh title="Terminal"
dygo secret get DATABASE_URL
```

`secret get` writes the raw value to standard output for scripts. Keep logs and command traces from capturing that output.

## Validate references

```sh title="Terminal"
dygo secret validate
dygo secret validate --env production
```

## Rotate the key

Back up the current key and encrypted files, then run:

```sh title="Terminal"
dygo secret rotate-key
```

The command prints its plan and prompts before writing. In v0.0.6 it supports `--yes`, but does not support `--dry-run`.

Store the new private key through your deployment secret channel. Do not commit `.dygo/secrets/master.key`.

External secret providers are not part of the current runtime.

## Environment files and editors

Encrypted files live at `config/secrets/development.yml.age`, `staging.yml.age`, and `production.yml.age`. One project-local master key protects all environments in this release. Back up that key securely; losing it can make every encrypted environment file unreadable.

`secret edit` defaults to `nano`. Select an editor with `--editor "code --wait"`. Secret names support root keys and dot-separated YAML paths, such as `database.url`. Environments must use the full names `development`, `staging`, or `production`.

## Record encryption keys

The `secret` Entity Field uses a separate data key stored inside the encrypted environment YAML under `_record_encryption`. Do not edit that mapping manually. Projects without secret Fields do not need a Record key.

```sh title="Initialize without replacing existing keys"
dygo secret record-key init --env development --dry-run
dygo secret record-key init --env development --yes
```

Missing keys prevent Record secret encryption and decryption. Ordinary Record reads never reveal secret values.

To rotate Record data keys:

1. Stop all servers, Workers, and other writers for that environment.
2. Back up the database, encrypted environment YAML, and existing master key. Store the master key separately and securely.
3. Review the target and perform the offline rotation.

```sh title="Terminal"
dygo secret record-key rotate --env production --offline --dry-run
dygo secret record-key rotate --env production --offline --yes
```

4. Wait for `Record key rotate complete`. Back up the updated encrypted YAML, then restart writers.

`--offline` confirms that you stopped writers; it does not stop them. If rotation is interrupted, keep writers stopped and rerun the same command. Saved progress reuses the new key and skips already rotated values. A missing old key or corrupt ciphertext requires repair from backup, not replacement of the entire key ring.

Old identities remain so older backups stay readable. Automatic old-key deletion is not supported. Do not edit credentials or rotate the master key during Record-key rotation.

`secret rotate-key` replaces the credential store's master key. `secret record-key rotate` re-encrypts Record values. They are separate operations.
