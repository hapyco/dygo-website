Create a working Dygo project with PostgreSQL and Studio. The commands below target [v0.0.8](/reference/status/), an early release whose APIs can still change.

## Before you start

You need Go 1.26.2 or later, Git, a running PostgreSQL server, and the [Dygo release binary](/start-here/installation/). Your PostgreSQL role needs permission to create the development database, or an administrator must create it first.

```sh title="Check your tools"
go version
git --version
dygo version
```

## Create a project

```sh title="Terminal"
dygo new my-system
cd my-system
```

Generation creates App source, `dygo.yml`, encrypted environment credentials, queue configuration, managed Core and Studio metadata, and `cmd/dygo/main.go`. It resolves Go dependencies by default. A schema snapshot is written after migration.

Use `--module example.com/team/my-system` when the project needs a specific Go module path. `--skip-tidy` defers dependency resolution; run `go mod tidy` yourself before compiling the runner.

## Configure PostgreSQL

The generated development secret points to:

```text
postgres://localhost/my_system_development?sslmode=disable
```

That default uses local PostgreSQL authentication. If your server requires another user, password, host, or database, edit the encrypted secret:

```sh title="Terminal"
dygo secret edit
```

Set `DATABASE_URL` in the editor. Do not put the plaintext value in `dygo.yml` or source control. The default editor is `nano`; select another with `--editor "code --wait"`.

```sh title="Terminal"
dygo secret validate
dygo db prepare
```

`prepare` creates the configured database if it is missing. It then runs the migration lifecycle: App state, Patches, metadata, access, and Fixtures. Review the displayed plan before confirming.

## Create the Administrator

```sh title="Terminal"
dygo setup
```

Enter the first Administrator's email, full name, and password. Setup owns this bootstrap; do not seed a shared Administrator password in Fixtures.

## Open Studio

```sh title="Terminal"
dygo dev
```

Open the ready URL printed by the command, normally [http://localhost:6790/](http://localhost:6790/). Sign in with the account you created. Keep the process running while you use Studio.

## Create your first Entity

In a second terminal in the project directory:

```sh title="Terminal"
dygo generate app crm
dygo generate entity crm/contact
dygo entity validate
dygo db migrate
```

Entity generation creates metadata, access, and Fixture skeletons. Add compiled behavior separately with `dygo generate hook crm/contact`. See [Entities](/build-apps/entities/) to define your Fields and [Access](/build-apps/access/) to grant non-Administrator users access.

## Diagnose setup

```sh title="Terminal"
dygo doctor
```

Doctor checks configuration, queues, secrets, PostgreSQL, metadata, routes, Fixtures, runner wiring, Studio assets, and initial setup. Follow [Troubleshooting](/run/troubleshooting/) when a check fails.
