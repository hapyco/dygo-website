Dygo distributes binaries for macOS, Linux, and Windows on [GitHub Releases](https://github.com/hapyco/dygo/releases). The current release is **[v0.0.8](https://github.com/hapyco/dygo/releases/tag/v0.0.8)**. See [Framework status](/reference/status/) for the release boundary.

## Before you install

Install Git and Go **1.26.2 or later** for generated projects. The release binary contains the CLI and Studio assets, but project generation runs `go mod tidy` and the project runner compiles App code. You also need a running PostgreSQL server for Record storage.

The release assets support `amd64` and `arm64` on all three operating systems. The Unix installer needs `curl` or `wget`, `tar`, and a supported SHA-256 tool. Install into a directory your account can write.

## macOS and Linux

```sh title="Terminal"
curl -fsSL https://dygo.dev/install | sh
```

The installer downloads the platform archive, verifies its checksum and embedded version, then replaces the managed binary in `~/.dygo/bin`.

If the directory is missing from `PATH`, add the line printed by the installer to your shell profile. For the current shell:

```sh title="Terminal"
export PATH="$HOME/.dygo/bin:$PATH"
dygo version
```

## Windows PowerShell

```powershell title="PowerShell"
irm https://dygo.dev/install.ps1 | iex
dygo version
```

Follow the installer's PATH instructions, then open a new terminal if needed.

## Pin a version or directory

Choose a published tag and use the installer hosted on that same release. `DYGO_VERSION` pins the CLI binary and can also downgrade it; it does not change a project dependency:

```sh title="Terminal"
curl -fsSL https://github.com/hapyco/dygo/releases/download/v0.0.8/install.sh | DYGO_VERSION=v0.0.8 sh
```

Use `DYGO_INSTALL_DIR` to change the destination:

```sh title="Terminal"
curl -fsSL https://dygo.dev/install | DYGO_INSTALL_DIR="$HOME/bin" sh
```

PowerShell reads the same environment variables. Set them before invoking the installer:

```powershell title="PowerShell"
$env:DYGO_VERSION = 'v0.0.8'
irm https://github.com/hapyco/dygo/releases/download/v0.0.8/install.ps1 | iex
Remove-Item Env:DYGO_VERSION
```

## Update an existing project

Commit or stash your project changes first. Project upgrades refuse a dirty Git worktree. Back up production data before applying metadata changes.

Re-run the installer to update the CLI. Run it outside the project, then review the project upgrade:

```sh title="Terminal"
curl -fsSL https://dygo.dev/install | sh
dygo version
cd my-system
dygo upgrade --check
dygo upgrade --dry-run
dygo upgrade
```

`upgrade` updates the project's Dygo dependency, managed runner files, tracked Core and Studio metadata, and cached Studio UI when the target version differs. `upgrade --check` compares the project dependency with the version embedded in the running binary. It does not check GitHub for the latest release. `--to` must match that binary; it does not download another release.

Apply the updated metadata before starting the project:

```sh title="Terminal"
dygo db migrate --dry-run
dygo db migrate
dygo doctor
dygo dev
```

Use `--yes` only after reviewing the corresponding upgrade or migration plan. Updating the global binary alone does not upgrade a project's dependency.

Homebrew and `go install` are not documented release installation paths. For installation, checksum, PATH, or upgrade failures, see [Troubleshooting](/run/troubleshooting/).
