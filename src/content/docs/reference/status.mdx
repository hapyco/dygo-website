The current release is **[Dygo v0.0.8](https://github.com/hapyco/dygo/releases/tag/v0.0.8)**, published October 2, 2026. These guides combine the v0.0.6 source audit with the verified v0.0.7 and v0.0.8 release changes described below. Dygo is in early development; APIs, commands, metadata, and operating procedures can change before a stable release.

## Available in the verified release

- Project generation, App repository installation, and managed project upgrades.
- App, Entity, Field, Page, access, Fixture, Job, Schedule, and Patch metadata.
- One transactional database migration lifecycle for App state, Patches, metadata, access, and Fixtures.
- Session login, Administrator bootstrap, roles, row conditions, and Field restrictions.
- Record CRUD, Single Entities, parent-owned collections, Tree Entities, and private/system Entity boundaries.
- Compiled Record Hooks, Entity actions, and the [public App SDK](/reference/sdk/).
- Durable Jobs, retries, timeouts, cancellation, manual retry, and recurring Schedules.
- App-owned Vue Pages, private saved filters, Record List/Tree views, command menu, and keyboard shortcuts in Studio.
- File attachment and CSV import/export interfaces, comments, diagnostic Logs, and in-app notifications with optional email delivery. See the known limitations below before relying on imports or attachment creation.
- Encrypted environment credentials and write-only encrypted Record secret Fields.
- Job `cron` shortcuts in UTC and Entity form-tab metadata, added in v0.0.6.

A generic Record screen for a Job Execution is distinct from a dedicated Job operations dashboard. Bundled Vue Page support is available; independently packaged Page renderers have the limitation described below.

## Still planned

- Declarative Workflow metadata for approval states and transitions. Compiled Entity actions are available now.
- Shared saved Views, grid/calendar/Gantt views, and a general Reports or dashboard framework. Apps can build their own Vue Pages.
- Specialized Schedule creation/editing screens and richer Job operations screens.
- OAuth, SSO, API keys, invitations, and password recovery.
- Compliance audit controls and automatic production backups.
- External queue backends, queue rate limits, retention policy, and dead-letter handling.
- Dynamic Go Hook loading and general public SDK config, secret, or metadata services.
- A consistent global CLI `--json` output mode and context-aware completion.

## Known limitations in the audited baseline

These follow-ups remain open after v0.0.8. Their presence in the UI or SDK is not a guarantee that the affected workflow succeeds. Follow the issue and release notes for a verified fix.

| Area | Tracked limitation |
| --- | --- |
| CSV imports | Interrupted import retries can duplicate target rows ([#143](https://github.com/hapyco/dygo/issues/143)). |
| Attachments | Required attachments cannot complete new Record creation ([#291](https://github.com/hapyco/dygo/issues/291)). |
| Access edge cases | System-ID and fetched-Field permission predicates can reject otherwise valid updates ([#296](https://github.com/hapyco/dygo/issues/296), [#297](https://github.com/hapyco/dygo/issues/297)). No permission bypass was demonstrated in these findings. |
| Process lifecycle | Git transport descendants and pending confirmation reads need further cancellation handling ([#298](https://github.com/hapyco/dygo/issues/298), [#299](https://github.com/hapyco/dygo/issues/299)). |
| Protected naming defaults | Format-naming inputs remain explicit. A defaulted naming token with a Field write restriction still needs a separate naming-default contract ([#304 disposition](https://github.com/hapyco/dygo/issues/304#issuecomment-5945630164)). |
| App Pages | Bundled Vue Pages work, but independently packaged renderer discovery and a versioned extension workflow remain open ([#265](https://github.com/hapyco/dygo/issues/265)). |

## Released in v0.0.8

[Dygo v0.0.8](https://github.com/hapyco/dygo/releases/tag/v0.0.8) contains four fixes from [PR #305](https://github.com/hapyco/dygo/pull/305):

- Installer cancellation interrupts and reaps the active download child.
- A fatal Worker error cancels sibling queues before bounded cleanup.
- Studio retains committed Record creation after failed navigation. A navigation retry does not submit the create again.
- Studio omits untouched database-backed defaults from new forms. Explicit edits retain Field write restrictions. Scoped create authorization checks the exact PostgreSQL defaults.

Defaulted format-naming inputs and collection payloads remain explicit. Before-create Hooks receive submitted input; omitted defaults are absent from that input and PostgreSQL supplies them at insertion. The protected naming-default limitation above remains open. Update the CLI and project with the [installation procedure](/start-here/installation/#update-an-existing-project).

## Released in v0.0.7

The [release notes](https://github.com/hapyco/dygo/releases/tag/v0.0.7) cover installer verification and replacement safety, delayed CLI progress on stderr, Record collision retries and snapshot locking, defaults-only creation, clearing optional typed values, attachment uploads on saved Single Entity settings, CSV import bookkeeping and count handling, Worker failure shutdown, and command-menu interaction improvements.

The release adds no commands or flags. Slow TTY operations use animated progress; CI and pipes use plain output. Stdout result contracts stay unchanged. Re-run the installer to update the CLI, verify `dygo version`, then review and apply the [project upgrade and migration](/start-here/installation/#update-an-existing-project). Project `upgrade` targets the running binary's version and does not update the global CLI. Discovery and uninstall commands remain unavailable.

## Verification boundary

The original v0.0.6 documentation audit compared the release source with framework commit `ff499ea75066618cb1bdcb57f88adc46f57da2ec`. Public SDK files, registered Record routes, migration lifecycle, project generation, and CLI reference behavior matched the release at that checkpoint. Examples are based on implemented contracts; this does not claim that every production deployment or integration has been tested.

The v0.0.7 release validation passed 1,236 Go tests with PostgreSQL 17, `go vet`, focused race tests, 110 Studio tests, and embedded builds. After publication, Linux AMD64 fresh installation and a public v0.0.6-to-v0.0.7 CLI/project upgrade passed, including real module resolution, runner builds, database preparation and migration, preserved test data, health checks, and Studio assets. Native installer checks also covered macOS ARM64 and Windows AMD64 with PowerShell 5.1 and 7. Linux ARM64, macOS AMD64, and Windows ARM64 were cross-built and inspected, but not executed natively. See the release notes for the complete evidence and remaining follow-ups.

The release team verified v0.0.8 with 1,260 Go tests using PostgreSQL and 114 Studio tests. Public fresh installation and an actual v0.0.7-to-v0.0.8 project upgrade passed. Native coverage included Linux AMD64, macOS ARM64, and Windows AMD64; the other published architectures were cross-built. This evidence is separate from the original documentation audit.

Versioned source links elsewhere in these guides retain the original v0.0.6 audit references; they are not claims that every API was independently re-audited at v0.0.7 or v0.0.8.
