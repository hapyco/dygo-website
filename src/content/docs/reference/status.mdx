These guides are verified against **[Dygo v0.0.6](https://github.com/hapyco/dygo/releases/tag/v0.0.6)**, published September 22, 2026. Dygo is in early development; APIs, commands, metadata, and operating procedures can change before a stable release.

## Available in the verified release

- Project generation, App repository installation, and managed project upgrades.
- App, Entity, Field, Page, access, Fixture, Job, Schedule, and Patch metadata.
- One transactional database migration lifecycle for App state, Patches, metadata, access, and Fixtures.
- Session login, Administrator bootstrap, roles, row conditions, and Field restrictions.
- Record CRUD, Single Entities, parent-owned collections, Tree Entities, and private/system Entity boundaries.
- Compiled Record Hooks, Entity actions, and the [public App SDK](/reference/sdk/).
- Durable Jobs, retries, timeouts, cancellation, manual retry, and recurring Schedules.
- App-owned Vue Pages, private saved filters, Record List/Tree views, command menu, and keyboard shortcuts in Studio.
- File attachment and CSV import/export interfaces, comments, diagnostic Logs, and in-app notifications with optional email delivery. See the known limitations below before relying on imports or attachment creation.
- Encrypted environment credentials and write-only encrypted Record secret Fields.
- Job `cron` shortcuts in UTC and Entity form-tab metadata, added in v0.0.6.

A generic Record screen for a Job Execution is distinct from a dedicated Job operations dashboard. Bundled Vue Page support is available; independently packaged Page renderers have the limitation described below.

## Still planned

- Declarative Workflow metadata for approval states and transitions. Compiled Entity actions are available now.
- Shared saved Views, grid/calendar/Gantt views, and a general Reports or dashboard framework. Apps can build their own Vue Pages.
- Specialized Schedule creation/editing screens and richer Job operations screens.
- OAuth, SSO, API keys, invitations, and password recovery.
- Compliance audit controls and automatic production backups.
- External queue backends, queue rate limits, retention policy, and dead-letter handling.
- Dynamic Go Hook loading and general public SDK config, secret, or metadata services.
- A consistent global CLI `--json` output mode and context-aware completion.

## Known limitations in the audited baseline

These framework issues describe failures found in the audited source. Their presence in the UI or SDK is not a guarantee that the affected workflow succeeds. Follow the issue and release notes for a verified fix.

| Area | Tracked limitation |
| --- | --- |
| CSV imports | Queued imports can fail at system Record bookkeeping ([#293](https://github.com/hapyco/dygo/issues/293)); status counts also need correction ([#295](https://github.com/hapyco/dygo/issues/295)). |
| Attachments | Studio upload on Single Entities is blocked ([#290](https://github.com/hapyco/dygo/issues/290)); required attachments cannot complete new Record creation ([#291](https://github.com/hapyco/dygo/issues/291)). |
| Forms | Defaults-only creation and clearing optional typed values need fixes ([#289](https://github.com/hapyco/dygo/issues/289)). |
| Record concurrency | Snapshot locking and random-name collision retry need correction ([#292](https://github.com/hapyco/dygo/issues/292), [#288](https://github.com/hapyco/dygo/issues/288)). |
| Access edge cases | Proposed updates must preserve system ID ([#296](https://github.com/hapyco/dygo/issues/296)); fetched-Field traversal needs a defined target access policy ([#297](https://github.com/hapyco/dygo/issues/297)). |
| Process lifecycle | Long-operation feedback, Worker failure draining, Git subprocess cancellation, and pending confirmations are being addressed ([#287](https://github.com/hapyco/dygo/issues/287), [#294](https://github.com/hapyco/dygo/issues/294), [#298](https://github.com/hapyco/dygo/issues/298), [#299](https://github.com/hapyco/dygo/issues/299)). |
| App Pages | Bundled Vue Pages work, but independently packaged renderer discovery and a versioned extension workflow remain open ([#265](https://github.com/hapyco/dygo/issues/265)). |

## Upcoming CLI release

CLI progress, lifecycle messages, or release changes under active development are not promised by this baseline. Check `dygo version` and the [published release notes](https://github.com/hapyco/dygo/releases) before adopting new behavior. An unreleased source change is not an installed binary feature.

## Verification boundary

The documentation audit compared the release source with framework commit `ff499ea75066618cb1bdcb57f88adc46f57da2ec`. Public SDK files, registered Record routes, migration lifecycle, project generation, and CLI reference behavior matched the release at that checkpoint. Examples are based on implemented contracts; this does not claim that every production deployment or integration has been tested.
